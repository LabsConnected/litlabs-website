fix: separate workspace, terminal, writeAccess, and approvalRequired concepts

The runtime status logic was conflating four independent concepts:
- workspace readiness (provisioned + mounted)
- terminal connection (WebSocket transport)
- write surface availability (can files be written)
- approval requirement (safety policy)

Previously: writeAccess = workspaceReady && terminalConnected, and
approvalRequired = !writeAccess. This meant a disconnected terminal
was reported as "approval required" — wrong on both counts.

Now each field is independent:
- executionAvailable = workspaceReady && terminalConnected (can run commands)
- writeSurfaceAvailable = workspaceReady || terminalConnected (a write surface exists)
- writeApprovalRequired = always true (policy — writes always need approval)
- terminalConnected = client WebSocket state (reported separately)
- voiceConfigured / voiceSessionConnected = separate from execution

- runtime-state.ts: add terminalServerReachable, writeSurfaceAvailable,
  voiceConfigured, voiceSessionConnected fields
- useProjectRuntime.ts: stop deriving writeAccess from terminal connection
- messages/route.ts: approvalRequired = true (policy), not !writeAccess
- project-runtime/route.ts: correct server-side state derivation
- runtime-context-injector.ts: update generateProjectStatusAnswer to
  report terminal disconnection and approval as separate facts;
  workspace.write tool now checks terminal connection, not approval
- useConnectionSummary.ts: document that writeAccess means "a write
  surface exists", not "approval is waived"
