# First 100 Users

> Practical acquisition and feedback plan. No fake users, testimonials, or metrics.

## Strategy

Sell outcomes, not features:
- Small business: "LiTT manages and updates your website."
- Creator: "LiTT creates, uploads and publishes your campaign."
- Developer: "LiTT fixes, tests and ships your code."
- Beginner: "Tell LiTT what you need and watch it do it."

**Delegated work with proof.** That's the money feature.

## Stage 1: First 5 users (founder demos)

### Who

- Founder's personal network
- Local small business owner who needs a website
- A creator friend who needs a landing page
- A developer friend who'll test the agent loop
- A non-technical friend (tests onboarding)

### How

- In-person or screen-share demo
- Founder drives the session
- Watch where they get confused
- Record the session (with permission)

### What we must learn

- Does the first-user journey work end-to-end?
- Where do users get stuck?
- Is the time-to-preview acceptable?
- Does LiTT's activity display make sense to non-technical users?
- Do users trust LiTT's output?
- What questions do they ask that LiTT can't answer?

### Success criteria

- All 5 users complete the first-user journey
- At least 3 return without prompting
- Zero data loss incidents
- Time-to-preview < 5 minutes for at least 3 users

### Feedback capture

- Session recording
- Founder notes (what confused them, what they liked)
- User's own words: "What did you expect? What surprised you? What was frustrating?"
- NPS-style: "Would you recommend this to a friend? Why?"

## Stage 2: First 20 users (invited beta)

### Who

- Extended network from stage 1 referrals
- Small businesses from local networking
- Creator/dev community members (Twitter, Discord, Reddit)
- Build-in-public audience

### How

- Invite-only with unique signup links
- Founder sends personal invite with 1-line pitch
- Each user gets a 15-min onboarding call (optional)
- Weekly check-in email

### What we must learn

- Does the product work without founder driving?
- What's the self-serve completion rate?
- Which features do users discover vs. need to be told about?
- What errors do users hit that founder didn't anticipate?
- Do users use voice? Canvas? Code editor?
- What do users want to build that LiTT can't do yet?

### Success criteria

- > 50% complete first-user journey without founder help
- > 30% return within 7 days
- Time-to-preview < 5 minutes for > 70% of users
- At least 5 users publish a website

### Feedback capture

- In-app feedback widget (simple: "How was that?" + text box)
- Analytics: drop-off points in first-user journey
- Error logs: what failures users hit
- Weekly email: "What did you build this week? What was hard?"

## Stage 3: First 50 users (expanded beta)

### Who

- Build-in-public clips on Twitter/X, TikTok, YouTube Shorts
- Hacker News "Show HN" post (when product is ready)
- Product Hunt launch (when first-user journey is solid)
- Indie hacker communities (IndieHackers, dev.to)
- Local small business networking groups

### How

- Public beta link with waitlist
- Build-in-public: share clips of LiTT building websites in real-time
- "LiTT built this in 3 minutes" → show the receipt
- Offer free first build to small businesses

### What we must learn

- What's the conversion rate from landing → signup → first build?
- Which acquisition channel produces the most engaged users?
- What's the most common first build request?
- Where does the product break under different use cases?
- What pricing model makes sense?

### Success criteria

- > 40% of signups complete first-user journey
- > 20% return within 7 days
- At least 10 published websites
- At least 3 users ask "can I pay for this?"

### Feedback capture

- Activation funnel analytics (landing → signup → onboarding → build → preview → modify → publish)
- Session replay (Hotjar/PostHog) for first 5 minutes
- Error rate monitoring
- User interviews with 5 users (30 min each)

## Stage 4: First 100 users (public beta)

### Who

- All of the above channels scaled
- SEO content ("AI website builder" long-tail)
- Partner referrals from stage 2-3 users
- Small business directories
- Creator communities

### How

- Public signup, no waitlist
- Freemium: free first build, credits for more
- Build-in-public: share milestones, user stories (with permission)
- Referral: "Invite a friend, both get credits"

### What we must learn

- What's the sustainable acquisition cost?
- What's the activation rate at scale?
- What features drive retention?
- What's the willingness to pay?
- What use cases expand beyond websites?

### Success criteria

- > 100 total signups
- > 30% activation (complete first build)
- > 15% weekly retention
- At least 5 paying users
- At least 20 published websites
- Error rate < 5% of sessions

### Feedback capture

- NPS survey after first publish
- Cohort retention analysis
- Feature usage analytics
- Pricing experiment (free vs. credits vs. subscription)
- User survey: "What would make you pay for this?"

## Activation metrics that matter

| Metric | Target | How to measure |
|---|---|---|
| Landing → Signup | > 10% | Analytics funnel |
| Signup → First build started | > 60% | Analytics funnel |
| First build → Preview ready | > 80% | Analytics + server logs |
| Preview → First modification | > 50% | Analytics funnel |
| Modification → Publish | > 30% | Analytics funnel |
| Signup → Return within 7 days | > 25% | Cohort analysis |
| Time to first preview | < 5 min | Server-side timing |

## What we are NOT doing

- Buying ads (too early)
- Fake testimonials
- Inflated user counts
- Launching on Product Hunt before first-user journey works
- Scaling acquisition before activation works
- Building features for 1 user's request

## The one number that matters

**How many users completed the first-user journey and came back the next day?**

If that number is growing, the product is working. Everything else is noise.
