# LiTT — Repository Instructions

Canonical, tool-agnostic agent instructions for this repository.
Specialized agent configs (`.devin-config.json`, `.devin/skills/`, `.clinerules`)
layer on top of this file — they do not override it.

## Product

LiTTree Lab Studios OS is an AI-powered creative and developer platform.
This repository powers the marketing/product website, the Studio app,
the terminal server, and the LiTT agent core (pnpm workspace monorepo).

## Core rules

- Inspect relevant files before changing code. Read the exact current region before editing.
- Prefer existing patterns, components, design tokens, and utilities.
- Keep changes minimal and scoped to the requested task.
- Do not rewrite unrelated files or refactor opportunistically.
- Do not expose, print, commit, or request secret values.
- Never edit `.env.local`, `.env*.local`, `.env.vercel-*`, or `.sb_anon_key`.
- Never modify production configuration, DNS, auth settings, or environment variables without explicit approval.
- Never push directly to `main`.
- Use feature branches and open a PR for ship-ready changes.
- Do not claim a task is complete until relevant validation succeeds.
- Use PowerShell syntax on Windows. Never mix cmd.exe, bash, and PowerShell.
- Do not downgrade Next.js, React, or Turbopack.
- Do not scaffold default Next.js/Tailwind boilerplate — the project is mature.

## Required validation

The canonical verification gate is:

```powershell
pnpm check
```

This runs, in order: `pnpm lint` → `pnpm type-check` → `pnpm test` → `pnpm build`.
If any step fails, stop and report the error; do not proceed to the next step.

For focused iteration:

| Check | Command |
|---|---|
| Lint | `pnpm lint` |
| Type-check | `pnpm type-check` (or `npx tsc --noEmit`) |
| Unit tests | `pnpm test` (Vitest + jsdom) |
| Build | `pnpm build` |
| E2E | `pnpm test:e2e` (Playwright) |
| Full gate | `pnpm check` |

For UI or Next.js changes:

1. Run `pnpm check` (or the individual steps above).
2. Test changed routes/components locally (`pnpm dev` on port 3001).
3. Summarize changed files, checks run, results, and known risks.

## Design direction

- LiTT should feel local-first, terminal-native, creative, calm, and highly capable.
- Preserve the "LiTT LOCAL" visual language.
- Favor dense but readable UI, restrained motion, accessible contrast, keyboard-friendly interactions.
- Avoid generic SaaS gradients, noisy cards, and fake dashboard metrics.
- `lucide-react` is pinned to `^1.24.0` (pre-rename) — prefer inline SVG for modern icons.

## Git workflow

- **Branch policy:** start from `main`, create a feature branch, never push directly to `main`, merge through a PR.
- **Branch format:** `feat/`, `fix/`, `chore/`, `docs/`, `experiment/`
- **Commit format:** `type(scope): concise imperative summary`
- Before a PR: inspect `git diff`, run `pnpm check`, include a concise testing note.
- Never force-push shared branches unless explicitly requested.

## Approval gates

Ask before:

- Installing or upgrading dependencies.
- Running database migrations (Supabase migrations live in `supabase/migrations/`; never write to `supabase/schema.sql` directly — it is regenerated by `supabase db pull`).
- Editing auth, billing, DNS, Cloudflare WAF, Vercel production settings, or Clerk production configuration.
- Deleting files or data.
- Git push, PR merge, deployment promotion, or any external write action.
- Running commands that can modify many files.

## Performance landmines

- **`AnimatedBackground.tsx`** — canvas animation on every page. Throttled to 30fps, pauses on tab hidden, respects `prefers-reduced-motion`. Do not regress this.
- **Do not add frequent `setInterval`/`setTimeout` in client components** without cleanup guards and visibility checks.
- `cleanDistDir: false` in `next.config.ts` avoids Windows EPERM on `.next/` cleanup — do not change.
- `serverExternalPackages: ["jose"]` fixes the middleware NFT build error — do not remove.
- `ignore-scripts=true` in `.npmrc` — postinstall scripts are skipped; install native deps manually.

## Response format

Always end work with:

- **Status:** done / blocked / needs decision
- **Changed:** files and concise purpose
- **Verified:** commands and outcomes
- **Next:** exactly one suggested action
